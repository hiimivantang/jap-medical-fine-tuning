# Spec — Experiment 01: Japanese medical LoRA fine-tuning on DGX Spark

Status: PRE-REGISTERED (written 2026-10-19 before any model was evaluated on any test split).
Changes after this point must be logged in `## Amendments` with reason and timestamp.

## 1. Question

Can a domain LoRA on Qwen3-8B beat (a) the untuned base and (b) a Japanese-specialised model of the same
size on Japanese medical extraction/classification, without degrading general Japanese understanding, and
how does it compare with an OpenAI reference on accuracy and cost?

## 4. Tasks and data

### 4.1 Task definitions (identical prompt templates across models)

- **Task A — medical entity extraction.** Input: Japanese clinical text. Output JSON
  `{"symptoms": [...], "diseases": [...], "medications": [...]}` with exact surface strings of entities the
  patient actually has / currently takes (affirmed). Negated, family-history and suspected mentions excluded.
  Metrics: entity-level micro P/R/F1 (strict: normalised-string match), per-type F1, document exact match,
  JSON validity, schema validity.
- **Task B — Japanese medical text classification.** 6-class clinical document category:
  `外来診療録 | 入院時記録 | 退院時サマリー | 紹介状 | 看護記録 | 検査・画像所見報告書`.
  Metrics: accuracy, macro-F1, per-class P/R, confusion matrix, invalid-label rate.
- **Task C — structured extraction.** Output JSON with fields `age` (int|null), `sex` (男性|女性|null),
  `chief_complaint` (str|null), `symptoms` (list), `negated_symptoms` (list), `past_history` (list),
  `family_history` (list), `medications` (list), `allergies` (list), `suspected_diagnosis` (list).
  Metrics: field-level accuracy (scalar exact; list = set-equality), per-field F1 for lists, document exact
  match, missing fields, unsupported extractions (predicted values not grounded in source text),
  schema compliance.

No task asks for diagnosis or treatment recommendations. `suspected_diagnosis` only copies what the text
states as suspected.

### 4.3 Synthetic data protocol

1. Sample a structured *spec* per note programmatically (seeded) from curated Japanese term inventories
   (symptoms, diseases, medications, allergies, document types). Gold labels = the spec, not the text.
2. Generator writes the note under explicit constraints (verbatim surface strings, negation/family/suspected
   phrasing, no PII, fictional).
3. Deterministic validator: every gold string must occur verbatim in the note; negated items must co-occur
   with a negation cue; forbidden-term check (gold entities from other categories must not leak); length
   bounds. Failing notes are dropped (count reported), never repaired by hand.
4. Term-inventory split: a held-out portion of the term inventory is ONLY used for test specs, so test
   entities include unseen surface strings (measures generalisation, not memorisation).
5. Near-duplicate filter: character 5-gram Jaccard ≥ 0.6 between any test note and any train note → drop
   the test note.
6. Manual review: a stratified sample (≥ 30 notes) is inspected and reported in `docs/DATA_QUALITY.md`.

### 4.4 Splits (seed 20261019, recorded with SHA-256 per file)

- train: synthetic (Qwen-gen) + MedTxt/RR-TNM conversions (JMED-LLM-disjoint)
- val: synthetic (Qwen-gen), used for checkpoint selection and early stopping only
- test-synth: synthetic (Qwen-gen), held-out term inventory, never seen in training
- test-xgen: synthetic (Nemotron-gen), held-out term inventory
- test-ext: JMED-LLM MRNER-disease, MRNER-medicine, CRADE, RRTNM (100 each)
- test-general: JCommonsenseQA test, JNLI test, JMMLU-Med (100)

Leakage controls: JMED-LLM documents are removed from training by text-overlap matching (≥ 0.5 char-5-gram
containment) against all JMED-LLM eval texts; the removal list is saved. The test files are never read by
the dataset builder for training (enforced by a unit test).

## 5. Training (E3)

LLaMA-Factory LoRA SFT, template `qwen3` with `enable_thinking: false` (matches inference prompt exactly).
Starting config: r=16, alpha=32, dropout 0.05, targets q/k/v/o (user-suggested); bf16; lr 1e-4 cosine,
warmup 3%; cutoff_len 4096; per-device batch 4 × grad-accum 4; 2 epochs; seed 42; gradient checkpointing.
Fireworks constraints: r ∈ [4,64], targets ⊆ {q,k,v,o,gate,up,down}_proj, no modules_to_save, bias none,
no DoRA → config satisfies them; checked by a validator script on the saved adapter_config.json.
Smoke test first (50 steps on 200 examples), then full run. Increase data/targets only if val justifies it.

## 6. Hypotheses and pre-registered decision rules

Primary endpoints:
- Task A: entity micro-F1. Task B: macro-F1. Task C: field-level accuracy.
- External: MRNER-disease F1, MRNER-medicine F1, CRADE accuracy, RRTNM accuracy.
- General: JCommonsenseQA accuracy, JNLI accuracy, JMMLU-Med accuracy.

Statistics: paired bootstrap over test items (10,000 resamples, seed 0) for differences; 95% percentile CI;
McNemar exact test for paired accuracy; Holm correction within each hypothesis family.

- **H1 supported** if E3 − E1 > 0 with 95% CI excluding 0 on ≥ 2 of the 3 synthetic primary endpoints
  (A, B, C) on test-synth AND the same direction holds on test-xgen. External JMED-LLM results reported
  separately as transfer evidence (not required for H1, but required for a "robust" claim).
- **H2 supported** if E3 − E2 > 0 with 95% CI excluding 0 on ≥ 2 of the 3 primary endpoints (test-synth and
  test-xgen pooled per task), i.e. the LoRA gain exceeds what general Japanese adaptation gives.
- **H3 supported (no material degradation)** if, for each of JCommonsenseQA, JNLI and JMMLU-Med, the lower
  bound of the 95% CI of (E3 − E1) is > −2.0 accuracy points (non-inferiority margin 2 pp).

## Amendments

All amendments below were made before any model was evaluated on any test split.

1. **2026-10-19 — Task C gains a `diagnoses` field (11 fields).** Confirmed current diagnoses needed their own
   field; otherwise they would be forced into `suspected_diagnosis` or dropped. Decided while writing the
   interface contract, before data generation.
2. **2026-10-19 — test_xgen volume.** The Nemotron generator follows long specs less reliably than the Qwen
   generator: 10% acceptance at 3 attempts (10 specs) and 25% at 6 attempts (40 specs), mostly from omitted
   required terms. The validator was NOT relaxed (that would create wrong gold labels). Instead test_xgen
   requests 1,000 specs with up to 6 attempts each. Consequence: accepted test_xgen notes skew toward simpler
   specs, so absolute scores on test_xgen and test_synth are not comparable; only within-set comparisons
   between conditions are interpreted.
3. **2026-10-19 — Real-text training data is small.** After the pre-registered leakage rule (containment
   ≥ 0.2 vs any JMED-LLM eval document), 40 MedTxt-CR case reports and 7 MedTxt-RR test reports remain
   (≈ 50 NER items). External transfer to JMED-LLM therefore depends mainly on the synthetic tasks.
4. **2026-10-19 — E2t (Swallow with reasoning) is run on the medical test sets only** (test_synth, test_xgen,
   test_ext), not on the 3,726 test_general items, because thinking-mode decoding of up to 4,096 tokens per
   item is ~20× more expensive and H3 concerns E3 vs E1 only.
5. **2026-10-19 — Secondary lenient entity F1.** A 5-item smoke test of the inference pipeline (GPT-4.1 on
   MRNER-disease, used only to verify plumbing) showed models extracting clause-length spans where JMED-LLM
   gold uses short spans, so strict F1 largely measures span-boundary convention. A secondary *lenient* F1
   (one-to-one matching where one normalised string contains the other) is reported alongside the
   pre-registered strict F1, which remains the primary endpoint. No hypothesis decision uses lenient F1.
6. **2026-10-19 — Independent code review fixes (before any E1/E3 prediction existed).** An independent
   reviewer found, and we fixed:
   (a) *Chief-complaint label noise* (~25% of notes stated a 主訴 the spec did not set, or listed several
   symptoms): two validator rules added; all splits re-validated from the original generation records.
   Final notes: train 1,367 / val 135 / test_synth 223 / test_xgen 215. The full training run in progress
   (step 370/600) was stopped and preserved as `results/training/qwen3-8b-jmed-lora-v0-ccnoise-aborted`;
   E3 is trained from scratch on the corrected data. E2/E4/E4b predictions remain valid (kept notes and
   prompts are unchanged; verified by prompt-token counts) and are scored on the reduced sets.
   (b) Decision logic now matches this document: significance uses Holm-adjusted p within each family;
   H1 cannot pass when test_xgen or a task is missing; H2 pools test_synth + test_xgen per task (paired
   bootstrap over concatenated items) as written in §6; H3 requires all three general tasks; any comparison
   with missing predictions is marked incomplete and blocks the decision.
   (c) MC parsing: with valid JSON only the `answer` field counts; prose fallback prefers an explicitly cued
   letter, ignores option ranges ("A〜D"), else takes the last lone letter. Doc-type free-text fallback only
   when no JSON was produced.
   (d) Reporting additions: whole-output JSON validity rate; lenient entity F1 uses maximum bipartite
   matching with a 2-character minimum. Runner stores a request fingerprint and never drops rows.
   Note: with n=100, JMMLU-Med non-inferiority at a 2 pp margin is nearly unattainable (the reviewer showed
   a lower bound of −0.03 with only two discordant items); H3 is therefore reported per task, with this
   power limitation stated.
7. **2026-10-19 — Host crash and E2t subsample.** The DGX Spark rebooted unexpectedly at ~17:55 during the E2
   latency profile (journal ends without panic/OOM/Xid/thermal entries; memory was 46% used; cause unknown).
   All completed artefacts were verified intact afterwards: git fsck clean, processed-data SHA-256 sums match,
   all 62 prediction files parse and are complete, adapter SHA-256 unchanged. The E2 latency profile was
   re-run. To limit GPU time-under-load, E2t (Swallow with native reasoning, ~1,000 tokens/item measured on
   4 items) is run on a seeded random subsample of 60 items per task (test_synth, test_xgen, test_ext;
   `jmedft infer --sample 60`), and compared with other conditions on the shared items only. E2t enters no
   hypothesis decision. vLLM `gpu_memory_utilization` lowered from 0.40 to 0.35 (memory headroom only; no
   effect on outputs).
