# Experiment 01 — Japanese medical LoRA fine-tuning of Qwen3-8B on an NVIDIA DGX Spark

Technical report · 2026-10-19 · all numbers from `experiments/01_finetuning/results/metrics/` (generated by
`jmedft evaluate` / `jmedft report`); design pre-registered in `docs/PREREGISTRATION.md` (commit `cbedb89`,
before any model was evaluated; amendments 1–7 logged with reasons, all before the E1/E3 evaluation except 7,
which concerns a crash and an optional arm).

## 1. Summary

A rank-16 LoRA adapter (15.3 M trainable parameters, 61 MB) trained for 2.6 h on one DGX Spark turned Qwen3-8B
into the best model in this comparison **on the Japanese medical tasks it was trained for**:

| Synthetic held-out test (223 notes) | Qwen3-8B | + LoRA (E3) | GPT-4.1 | GPT-5.4-mini | GPT-6.1-sol† |
|---|---|---|---|---|---|
| A — entity extraction, micro-F1 | 0.951 | **0.997** | 0.962 | 0.956 | 0.949 |
| B — document type, macro-F1 | 0.622 | **0.988** | 0.711 | 0.766 | 0.761 |
| C — structured extraction, field accuracy | 0.906 | **0.993** | 0.902 | 0.940 | 0.974 |

† GPT-6.1-sol was run on 2026-10-30 as a post-hoc addendum (see the addendum section at the end): not
pre-registered, added after all other results were known.

The gains hold on notes written by a different model family (Nemotron), and on the one external real-text task
whose annotation convention was represented in training (JMED-LLM MRNER-disease strict F1 0.265 → 0.473; lenient F1
0.544 → 0.645). It beats GPT-4.1 there only under the strict, span-convention-sensitive metric (0.110); under lenient
matching GPT-4.1 (0.707) and GPT-5.4-mini (0.727) remain ahead.
On external tasks that were untrained (adverse-event certainty, TNM staging) or nearly so (medication values: 3
training items) the adapter
did not help and is 3–8 points below the base model (not statistically significant) and 10–28 points below the
OpenAI references. General Japanese ability was preserved (non-inferior within 2 points).

| Hypothesis | Decision (pre-registered rule) |
|---|---|
| H1 — domain LoRA improves Japanese medical extraction/classification | **Supported** (3/3 endpoints, both synthetic test sets, Holm-adjusted p < 0.0001) |
| H2 — benefit beyond general Japanese adaptation (vs Qwen3-Swallow-8B) | **Supported** (3/3 endpoints, pooled, p < 0.0001; also vs Swallow with reasoning on a 60-item subsample) |
| H3 — no material degradation of general Japanese understanding | **Supported** (all three lower CI bounds > −2 points; tightest −1.6) |

What this does and does not show is in §8 (limitations). The short version: the adapter learned the target
task *and its annotation conventions* very well; it did not acquire broader medical reasoning.

## 2. Setup

### 2.1 Hardware and software (verified, see `results/manifest.json`)

NVIDIA DGX Spark — GB10 Grace Blackwell (sm_121), 128 GB unified memory, aarch64, Ubuntu 24.04.4, driver 580.173.02,
CUDA 13.0. Training: LLaMA-Factory 0.9.5 in an isolated venv (torch 2.11.0+cu130, transformers 5.6.0, peft 0.18.1),
following NVIDIA's `playbook-llama-factory` pattern. Inference: `vllm/vllm-openai:v0.31.0` (arm64), base model and
LoRA served from one container. Evaluation/reporting: torch 2.14.1+cu130, transformers 5.20.1 (main venv).

### 2.2 Conditions (identical prompts, JSON schemas, parsers and scorers)

| ID | Model (pinned revision) | Decoding |
|---|---|---|
| E1 | `Qwen/Qwen3-8B@b968826` | greedy, thinking off, max 1,024 tokens |
| E2 | `tokyotech-llm/Qwen3-Swallow-8B-RL-v0.2@9218f48` (Japanese CPT+SFT+RL, built on Qwen3-8B-Base) | same as E1 |
| E2t | same as E2, native reasoning on (model card: "designed to perform reasoning by default") | T=0.6, top-p 0.95, top-k 20, max 4,096; **seeded 60-item/task subsample** |
| E3 | E1 + this LoRA | same as E1 |
| E4 | OpenAI `gpt-4.1-2025-04-14` | temperature 0 |
| E4b | OpenAI `gpt-5.4-mini-2026-03-17` | reasoning effort low |
| E1r / E3r | E1 / E3 with `repetition_penalty 1.1` | post-hoc sensitivity on test_ext only (not pre-registered) |

The Medical-Qwen3-Swallow-8B arm (E2m) listed as optional in the design was not run; see §9.

### 2.3 Tasks

All tasks ask for a JSON object; outputs are scored by deterministic code (no LLM judge). Prompts, schemas and
real examples: `README.md` → *Tasks*; full contract: `docs/INTERFACES.md`.

- **A — entity extraction**: symptoms, diseases, medications currently applying to the patient, verbatim; excludes
  negated, suspected and family-history mentions. Strict entity micro-P/R/F1 after NFKC normalisation; document
  exact match; JSON/schema validity. Secondary: lenient F1 (one-to-one containment matching).
- **B — document type** (6 classes: 外来診療録, 入院時記録, 退院時サマリー, 紹介状, 看護記録, 検査・画像所見報告書).
  Macro-F1 (primary), accuracy, per-class P/R, confusion matrices. The generator was forbidden to write the type name.
- **C — structured extraction** (11 fields: age, sex, chief complaint, symptoms, negated symptoms, past history,
  family history, medications, allergies, diagnoses, suspected diagnoses). Field accuracy (primary), document exact
  match, missing fields, unsupported (not-in-text) values, schema compliance.

### 2.4 Data (licences verified on primary sources; `docs/DATASETS.md`)

| Set | Source | Size | Use |
|---|---|---|---|
| train / val | Synthetic notes from `Qwen/Qwen3.8-27B-FP8` (Apache-2.0) + 47 MedTxt documents (CC BY 4.0) | 1,367 + 135 notes (4,151 / 405 records) | training, checkpoint selection |
| test_synth | Synthetic, same generator, 25% of vocabulary held out | 223 notes × 3 tasks | H1, H2 |
| test_xgen | Synthetic, different generator `nvidia/NVIDIA-Nemotron-3.5-Lightning-30B-A3B-NVFP4` (OpenMDW-1.1) | 215 notes × 3 tasks | H1 (direction), H2 |
| test_ext | JMED-LLM (sociocom@3774a34): MRNER-disease, MRNER-medicine, CRADE, RRTNM — real case/radiology reports, human annotations, CC BY 4.0 | 4 × 100 | external transfer |
| test_general | JGLUE v1.3 JCommonsenseQA (1,118), JNLI (2,508); JMED-LLM JMMLU-Med (100) — CC BY-SA 4.0, evaluation only | 3,726 | H3 |

Synthetic gold labels come from the sampled specification; a deterministic validator rejects any note whose text
does not support its labels (verbatim terms, negation and hedge cues, section context, chief complaint, PII patterns,
leakage of type names). No note was edited by hand; 76% of training specs (1,367/1,800) yielded an accepted note (89% at generation; the rest were rejected by later, stricter validator rules). Leakage controls: JMED-LLM
documents overlap MedTxt heavily (107/148 case reports are verbatim sources), so every MedTxt document with ≥ 0.2
character-5-gram containment against any of the 400 JMED-LLM test documents was removed (max remaining 0.192);
MedTxt-RR training reports were excluded entirely (same radiology cases); no TNM or ADE-certainty training data was
used. Test notes with Jaccard ≥ 0.6 to any training note would be dropped (none were; max 0.187). `jmedft data
validate` re-checks all of this and SHA-256 sums every file. No OpenAI output was used for training.

### 2.5 Training

LoRA r=16, α=32, dropout 0.05, targets q/k/v/o_proj, bf16, lr 1e-4 cosine, warm-up 3%, batch 4 × grad-acc 4,
2 epochs (520 steps), seed 42, gradient checkpointing, LLaMA-Factory template `qwen3` with thinking disabled (the
training prompt is byte-identical to the inference prompt; verified by test). Smoke test (30 steps) passed first.
Checkpoint chosen by lowest validation loss (pre-registered): step 300, val loss 0.00344 (steps 100–520: 0.00714,
0.00416, 0.00344, 0.00363, 0.00358, 0.00360). Wall time 9,311 s. Adapter SHA-256 `9a031e04…5fbc`.

The adapter passes all Fireworks AI and vLLM LoRA constraints (rank 4–64, allowed target modules, no
`modules_to_save`, bias none, no DoRA/rsLoRA, safetensors): `results/adapter_compatibility.json`. It was **not**
uploaded to Fireworks (Qwen3-8B adapters require an hourly-billed dedicated deployment; needs your approval).

Concrete examples (`README.md` → *Tasks* has the full notes):

- *Missed assessment-section diagnosis* (base model's commonest Task A error). test_synth-00139: 「A: 痛風 / 脂質異常症の可能性」.
  E1 returns diseases `["乳癌"]`; E3 and GPT-4.1 return `["乳癌", "痛風"]` and correctly omit the "possible" 脂質異常症.
- *Span convention.* test_synth-00006 「肩こりは認めない」: E1 and GPT-4.1 put `"肩こりは認めない"` in
  `negated_symptoms`; gold and E3 have `"肩こり"`. Both also promoted the symptom 記憶障害 listed under 印象 to a
  confirmed diagnosis; E3 did not.
- *Annotation scope.* GPT-4.1's Task A "errors" are mostly real clinical findings the synthetic gold does not label
  (90 "extra finding", e.g. imaging findings such as 斑状陰影 or 圧痛): the prompt says 「症状・所見」, the gold only lists
  scripted symptoms. GPT-4.1 almost never misses (2) or hallucinates (0). This is a property of the benchmark,
  and part of what E3 learned is this house convention.
- *Document type.* E1 almost never predicts 看護記録 (recall 6%; 121/223 notes labelled 外来診療録); E3 98%. Some
  synthetic "nursing records" read like physician summaries (test_synth-00004), so part of E3's Task B gain is
  learning the generator's style — the gain shrinks from 0.988 (same generator) to 0.789 (Nemotron notes).
- *Swallow without reasoning* emits fragmented JSON on ~13% of Task A outputs
  (`{"symptoms":[…]},{"diseases":[…]},{"medications":[…]}}`), losing 137 entities to formatting alone; with
  reasoning on, its scores rise substantially at ~10× the output tokens (978 vs 95 per request on the same 600 items).

## 4. Results — external human-annotated benchmark (JMED-LLM)

| | E1 | E1r† | E2 | E2t* | **E3** | E3r† | E4 GPT-4.1 | E4b |
|---|---|---|---|---|---|---|---|---|
| MRNER-disease, strict F1 (primary) | 0.265 | 0.277 | 0.171 | 0.119 | **0.473** | 0.518 | 0.110 | 0.193 |
| MRNER-disease, lenient F1 (secondary) | 0.544 | 0.557 | 0.534 | – | 0.645 | 0.681 | 0.707 | **0.727** |
| MRNER-medicine, strict F1 (primary) | 0.249 | 0.267 | 0.171 | 0.502 | 0.215 | 0.215 | 0.389 | **0.422** |
| MRNER-medicine, lenient F1 (secondary) | 0.419 | 0.449 | 0.293 | – | 0.296 | 0.305 | 0.708 | **0.712** |
| CRADE (ADE certainty, 4-way) acc. | 0.500 | 0.500 | 0.300 | 0.567 | 0.420 | 0.420 | 0.520 | 0.550 |
| RRTNM (TNM staging) acc. | 0.770 | 0.770 | 0.680 | 0.800 | 0.690 | 0.690 | 0.910 | **0.970** |

\* 60-item subsample (lenient F1 not computed for it). † post-hoc `repetition_penalty 1.1`, not pre-registered.

E3 − E1: MRNER-disease +20.8 [+15.1, +26.6] (p_Holm < 0.001); MRNER-medicine −3.4 [−9.6, +3.0]; CRADE −8.0
[−18.0, +1.0]; RRTNM −8.0 [−16.0, 0.0] (none of the three significant). Interpretation:

- **MRNER-disease** is the only external task whose labelling convention appears in training (47 MedTxt case
  reports, JMED-LLM-disjoint). The gain is mostly *less over-extraction*: "extra finding" errors fall from 923 to 244.
  Under strict matching every model is low because the human gold uses short spans (e.g. 「胃癌」) where models return
  clauses. E3's strict-F1 lead over GPT-4.1 (0.473 vs 0.110) is largely that span convention: under lenient matching
  E3 improves on its base (0.544 → 0.645) but GPT-4.1 (0.707) and GPT-5.4-mini (0.727) stay ahead.
- **Runaway repetition** is the clearest regression: E3 hit the 1,024-token limit on 37/400 external items (E1: 1),
  repeating a drug or finding name, on long real reports that are out of distribution relative to the ~200-character
  synthetic notes. A standard `repetition_penalty 1.1` cut this to 7/400 and lifted MRNER-disease to 0.518, but did
  not recover MRNER-medicine (0.215) — that task's "drug values" question had only 3 training items. The penalty also
  helps the base model slightly (E1r), so on MRNER-medicine the penalised base (0.267) stays ahead of E3r (0.215).
- **CRADE / RRTNM** had no training data at all. E3 shifts CRADE predictions toward "certainly ADE" and almost never answers
  "unlikely" (2 vs 25 gold): fine-tuning on a binary stated-vs-suspected convention mis-calibrated a 4-level judgment.
- **The OpenAI references remain clearly stronger on untrained medical reasoning** (RRTNM 0.91–0.97 vs 0.69–0.77).

| | E1 | E2 | **E3** | E4 GPT-4.1 | E3 − E1 [95% CI] | non-inferior (> −2)? |
|---|---|---|---|---|---|---|
| JCommonsenseQA (1,118) | 0.903 | 0.926 | 0.897 | 0.970 | −0.6 [−1.6, +0.4] | yes (tightest) |

The JMMLU-Med difference is 6 discordant questions (6–0); read it as "no degradation", not as a knowledge gain.
Power note: with n = 100 the JMMLU-Med non-inferiority test is fragile — its lower bound (+2.0) rests on those 6
questions; even a 1–1 split of discordant questions gives a 95% CI of [−3.0, +3.0] and would fail the −2-point
margin (checked with the same paired bootstrap).
These public benchmarks may be in the pre-training data of every model (contamination inflates absolute scores);
paired differences between E1 and E3, which share the base weights, are unaffected.

## 6. Efficiency and cost (measured)

Mixed synthetic workload, ~490–510 prompt tokens per request. Local numbers on one DGX Spark with bf16 weights and an
idle GPU; OpenAI numbers from the public API on the same items.

| | Single-stream p50 / p95 (s) | Mean output tokens | Batched throughput |
|---|---|---|---|
| E1 Qwen3-8B (Spark) | 4.33 / 10.37 | 68 | 14,830 req/h (c=32) · 282 output tok/s |
| E3 Qwen3-8B + LoRA (Spark) | 4.51 / 10.54 | 67 | 14,260 req/h (c=32) · 264 output tok/s |
| E2 Swallow (Spark) | 4.56 / 13.96 | 80 | 8,870 req/h (c=32) |
| E4 GPT-4.1 (API) | 1.06 / 1.45 | 75 | — (API scales out) |
| E4b GPT-5.4-mini (API) | 1.46 / 2.04 | 164 (incl. reasoning) | — |

- **Latency:** a single Spark decodes bf16 Qwen3-8B at ~13 tokens/s per stream (13.4 E1, 12.9 E3; memory-bandwidth
  bound), so per-request
  latency is ~4× GPT-4.1's. The LoRA adds ~4% latency.
- **Cost:** GPT-4.1 costs **$1.62 per 1,000 requests** for this workload (list price, 2026-10-19:
  $2.00 / $8.00 per 1M input/output tokens); GPT-5.4-mini $1.12. At the measured 14,260 req/h, a fully utilised Spark
  serving E3 matches GPT-4.1's per-request cost at an all-in **$23.2/hour**; any lower amortised hardware + power cost
  makes it cheaper. We did not measure a Fireworks deployment; at the listed on-demand H100 price ($8/h) an 8B
  deployment would need ≥ 4,930 req/h to beat GPT-4.1 per request (an assumption to verify, not a result).
- **Not yet optimised:** FP8/NVFP4 weights, speculative decoding and larger batch sizes were not tried.

## 7. Integrity checks performed

Pre-registration with dated amendments; deterministic seeds (data 20261019, training 42, decoding 0, bootstrap 0);
leakage filters with measured overlaps; held-out vocabulary; a second generator; an external human-annotated test;
identical prompts/decoding/scoring across conditions (unit-tested); training prompt = inference prompt (unit-tested);
no LLM judge; an independent code review before E1/E3 were scored found 1 critical and 6 major defects (chief-complaint
label noise, vacuous hypothesis rules, unapplied Holm correction, unpooled H2, lenient MC parsing, silent missing
predictions) — all fixed, training restarted on corrected data, recorded as amendment 6. 177 unit tests pass.

## 8. Limitations

1. **Synthetic in-distribution gains overstate real-world gains.** test_synth shares the training generator. The
   cross-generator set and the external benchmark exist to bound this; Task B in particular partly measures generator
   style (0.99 → 0.79 across generators).
2. **The external benchmark is small** (100 items/task; CIs ±8–10 points) and only one of its four tasks was
   represented in training. External transfer is task-specific, not general.
3. **Only ~50 real documents survived the leakage filter.** Real-text training signal was minimal.
4. **Annotation-scope mismatch** in Task A's prompt (症状・所見) vs gold (scripted symptoms only) penalises literal
   readers such as GPT-4.1; paired comparisons are unaffected, absolute levels are.
5. **Swallow comparison:** with reasoning off (identical decoding to E1/E3) Swallow underperforms its design point;
   with reasoning on it improves markedly but was only measured on a 60-item subsample. E3 still beats it on every
   synthetic task, but the external picture is mixed (E2t is better than E3 on MRNER-medicine, CRADE and RRTNM).
6. **Repetition loops** on long out-of-distribution documents (9% of external items) — fixable at decoding time
   (7/400 with a repetition penalty) but must be addressed before production.
7. **Host instability:** the Spark rebooted once during the run (cause unknown; no data lost; §amendment 7).

## 9. Recommendations for Experiment 2

1. **Pre-register use-case tasks** that match Nihin Media's products rather than generic capability:
   MedGen question understanding (intent + PICO + search terms), cited answers from fixed passages (citation precision/recall,
   correct abstention, numbers-in-citation checks), radiology finding certainty (MedTxt-RR test, 56 clean reports),
   pharmacovigilance ADE detection (MedNLP-SC SM, licence to re-verify).
2. **Real, customer-representative data** is the highest-value change: ~200 de-identified physician questions or notes
   from Nihin as a held-out test set, plus a few hundred for training under a data agreement.
3. **Diversify synthetic data:** ≥ 2 generators for training, longer notes (match real document length), the
   annotation guideline written explicitly into the generator prompt.
4. **Fix the loop failure mode:** long real-text training examples, `repetition_penalty`/frequency penalty or an
   entity-count stop at inference; track truncation rate as a release gate.
5. **Broaden adapter capacity carefully:** try all-linear targets (q/k/v/o + gate/up/down, still Fireworks-compatible)
   and r=32 only if the external set shows under-fitting; keep checkpoint selection on validation data.
6. **Serving economics:** benchmark FP8/NVFP4 Qwen3-8B on the Spark and a Fireworks dedicated deployment (needs
   approval; billed hourly) to replace the cost assumption in §6 with a measurement; multi-LoRA (one base, one
   adapter per product) on both.
7. **Run the optional Medical-Qwen3-Swallow-8B arm** (E2m, Apache-2.0) as the "off-the-shelf Japanese medical model"
   baseline; check its unreleased training data for overlap with the evaluation sets first.

## Post-hoc addendum (2026-10-30) — GPT-6.1 reference (E5_gpt61sol)

Added on the user's request **after all results above were known**, so it is not part of any pre-registered
hypothesis; it is descriptive. Model `gpt-6.1-sol`, reasoning effort low, `max_completion_tokens` 4096 — the
same decoding family as E4b. Same prompts, same deterministic scoring. 1,714 requests (both synthetic test
sets and all four JMED-LLM tasks), 0 errors, $3.20 at list prices. Results:
`results/metrics/scores_e5_addendum.json` (scores) and `comparisons_e5_addendum.json` (paired contrasts,
the same clustered bootstrap as elsewhere). Every original result file was left byte-for-byte unchanged
(verified by checksum before and after).

**Synthetic tests: the LoRA beats GPT-6.1-sol on every task, more clearly than it beats GPT-4.1.**
E3 − E5, Holm-adjusted p < 0.001 everywhere: test_synth A +0.048, B +0.227, C +0.020; test_xgen A +0.052,
B +0.196, C +0.034. GPT-6.1-sol is a better classifier and structurer than GPT-4.1 (B 0.761 vs 0.711;
C 0.974 vs 0.902) but slightly worse at strict span extraction (A 0.949 vs 0.962).

**External real documents (JMED-LLM, 100 items per task): the same mixed picture as for GPT-4.1.**

| test_ext | E3 LoRA | E4 GPT-4.1 | E4b GPT-5.4-mini | E5 GPT-6.1-sol |
|---|---|---|---|---|
| MRNER-disease strict F1 | **0.473** | 0.110 | 0.193 | 0.392 |
| MRNER-disease lenient F1 | 0.645 | 0.707 | 0.727 | **0.779** |
| MRNER-medicine strict F1 | 0.215 | 0.389 | 0.422 | **0.665** |
| CRADE accuracy | 0.420 | 0.520 | 0.550 | **0.630** |
| RRTNM accuracy (untrained) | 0.690 | 0.910 | 0.970 | **0.960** |

E3 − E5: disease strict +0.081 (p = 0.004); medicine −0.45, CRADE −0.21, RRTNM −0.27 (all p ≤ 0.002,
E5 ahead). The LoRA keeps its edge on the one task whose annotation convention it was trained on; on the
